## 打开验证入口

1. 在 Unity Hub 添加并打开上述 worktree，使用 Unity `6000.5.5f1`。不要打开 main 做本轮验收。
2. 打开 `Assets/Scenes/Validation/Phase12CustomerQueue.unity`，检查 Console 没有 compile error，再按 Play。
3. 验证场景会自动准备 Cash Register、Coffee Machine 和 Pick-up 的可营业布局。下方 P12 panel 显示到店倒计时、Register、三项容量和顾客状态。
4. 顾客每隔随机 1～5 **游戏秒**尝试入店。入口或路径暂时被占用时，倒计时停在0并保留一位待入场顾客，安全后入场才抽取下一轮；容量或实际队伍站位已满时停止生成，腾出容量后重新计时。
5. “让队首离开”只处理已经到队首的顾客；“修复后重试”在修复布局后重新验证路径。

本次M-003重测：重新Play默认验证布局，先等四位全部Queued，再点“让队首离开”；等前一位消失、后方完成前移，再点下一次，直到排空。然后在装修中把柜台分散、保持服务设施有效，重复同样操作。观察绕行不穿家具、不穿前方角色、不瞬移；若失败，请保留下方状态的具体“入店/前移/离场”原因和布局。

角落视觉可顺便观察：把收银柜台摆到原图那类场边有效位置，Confirm→Done→1x，等待新客排队。看尾部是否利用角落安全位置、直段间距是否均匀、离场后是否跟进。最小1.0m、微调最多1.25m；短段若需更大间距就保留原段，人物仍给边界留身体空间。自动角落case为Cash Grid(0,5)，不是原图精确坐标；不承诺每个空格都能站人或每种布局八位。旧顾客跨墙边屏障的重排被本次Decor reset规则替代，不能称为导航修复。

正常营业的前移仍各自独立：队首离开后，第二位开始向前，第三位可以在第二位仍行走时安全跟进。窄路里距离不足允许暂时停等；移动中Pause应全部原位暂停，恢复后继续。装修完成后的旧顾客会清空，新顾客使用新布局入队。

图2～4的布局可用于同一轮复测：空的员工工作位置可以成为排队站位，实际有人时避让。把收银柜台移到咖啡柜台后方，Confirm→Done→1x，等新客入队，再逐位离场。自动测试覆盖近似Cash Grid `(4,5)`、`(6,5)`、`(7,6)`，其余柜台默认；不等于原图精确坐标。若移动失败，保留完整入店/前移/离场原因。

已确认装修并Done后，旧八位也会全部清理；新布局只有七个安全站位时，只接纳能安全入队的新客。地面空着不一定能作为等待目标：若被前方角色与家具围住，系统不会生成该站位。

本轮追加：先等待五位顾客入队，再反复让队首离开与自动补客，观察尾客是否跟上。自动测试已覆盖只移动收银台、营业中装修、15/30/60/120fps及真实Editor帧时序；截图估算布局为收银台Grid `(2,6)`、咖啡柜台 `(5,4)`、Pick-up柜台 `(6,6)`，不是你的原图精确坐标。顾客在畅通路线按1.2m/游戏秒请求移动；真实障碍仍允许安全停下，转身等待与每段最后不足一步的距离仍会缩短。

门口蓝色2×2区域仅禁止放家具/物品，人物可以经过四格并用作路线；排队等待slot仍避开该区域。最新自动测试已走过四格，并在入口旁Grid `(2,0)` 有空柜台的相近布局中完成三位顾客入队、前移、离场。请用原截图布局重新Play，先等三位Queued，再逐位点离场，观察后方是否前移、最终顾客及容量是否归零。这项自动测试不代表原截图所有坐标/旋转已验收。

入店可与已有入店、前移或离场同时进行；进出交叉/对向、入口被占、队尾有静止/外部人物或前客未满足安全腾位条件、目标会挡住前客后续路线时，新客等待。本Flow的活动入店前客临时经过队尾时，可以在完整路线和实际身体安全保护下预测腾位；单纯“有顾客正在移动”不禁止入店。冲突尝试不创建角色、不占容量，并按后续随机interval再试，不积压补发。离场按钮规则保持：入店或前移中不接受新的离场请求，上一位尚未抵达出口时也不接受下一次离场。实际人数仍受容量、slot数量和安全路线共同限制。

`Entering` 是入店，`Queued` 是抵达站位，`Advancing` 是前移，`Exiting` 是离场，`Blocked` 是保留占位等待修复。容量 `Used` 包含 Reserved 和 Occupied；退出请求会取消未用的 Pick-up，实际离开柜台才释放 Counter，抵达出口才释放 Total。
